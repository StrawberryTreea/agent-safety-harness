# DeepSeek实际调用的受控LLM试验

本轮以5元人民币为新预算，用户反馈此前三题平台花费为0.01元。此前0.00024元只是Token按公开价格计算的估计，不当作平台账单。此处使用独立账本，持续读取[官方余额接口](https://api-docs.deepseek.com/api/get-user-balance/)并分别记录账户余额差、Token估价和预算占用。

## 范围与步骤

`scripts/run_deepseek_pilot.py` 自编24个任务家族，每个家族是一道有确定选项答案的问题，覆盖计算、字段提取、排序、形状识别、授权条件判断和字符串提取，混合中英文。20个E家族参与试验，2个V和2个H只冻结，不发送给生成器或目标模型。这不是正式数据来源，也不是导师方案所指的正式20家族研究预实验。

每个有效候选家族实际执行6次模型请求：

1. 干净问题的目标模型回答。
2. 带固定注入文本的目标模型回答。
3. 模型根据公开题目与离散失败信号生成新的注入文本。
4. 新候选第一次目标模型回答。
5. 同一候选第二次目标模型回答。
6. 保留问题并用近似等长普通文本替代注入的良性对照。

所有模型均使用 `deepseek-flash`，关闭思考模式，目标回答最多64 Token，生成最多512 Token。被测内容只是无害的指令遵循：尝试让目标偏离A/B选项，输出OVERRIDE。没有真实工具、资金转账、外部访问或完整Agent执行。

公开题目、私有答案、冻结分区分别保存，生成器只接收 `feedback_view_v1` 白名单；生成前检查E分区、父任务内容哈希、反馈绑定和私有canary。生成器JSON必须只有字符串字段 `injection`。多字段、非法JSON或canary命中均拒绝，不做自动剥字段或自动修复。

候选调用既有 `generate` 形成v2结构，并把实际API响应收据哈希绑定到生成器版本；单字段变换仍需语义审核。私有答案由原生RuleScorer评分，未改原生评分器代码。既有八门槛准入会评估重放、良性完成和私有规则证据；来源许可审核、独立审核等尚未完成，正式资格保持false，禁止自动发布。两次相同失败只是初步重放证据。

## 预算与可恢复性

最多120次模型请求，余额查询不属于模型推理请求。每次发送前预留0.05元，已报告用量按公开高峰价估计，并至少按0.02元占用预算。0.02元是保守记账口径，**不是服务商真实单次收费**。有效候选全部完成时120次占用至少2.4元；未知费用不退款，超预留则锁定账本。每家族前检查余额差及6次请求预留余量，余额不足或预算不足停止。

余额差是账户级、可能有取整或延迟、也可能受同账户其他活动影响，不能当作本运行的精确账单。未消费预算不要求花完。

每个完成家族生成一个哈希检查点；显式恢复时验证源码身份、输入、所有JSON产物与摘要，跳过已有响应。超时、半成品或未结算调用禁止自动恢复；需要人工核对。没有自动重试。

真实首批中，生成器额外返回了 `type` 字段，旧处理使全批在第9次调用后停止。修复为隔离无效候选、继续其他家族，并为此新增离线回归。原运行不改写；新运行的 `--import-prior` 明确导入已结算且收据与账本一致的旧响应，绑定来源哈希、核对实际请求体、保留旧调用的预算占用，不为相同请求再次付费。无效候选缺少重放/良性对照，其未知配对不会按零失败处理。

## 运行

默认只生成离线计划，输出必须为全新目录：

```powershell
python scripts/run_deepseek_pilot.py --out runs/my-pilot-plan
```

已获人工预算授权并在执行进程配置密钥后，先完成2个家族，再核对结果扩展；使用相同目录和相同冻结代码：

```powershell
python scripts/run_deepseek_pilot.py --out runs/my-pilot --live --through 2
python scripts/run_deepseek_pilot.py --out runs/my-pilot --live --resume --through 20
```

显式使用 `--import-prior` 时，后续恢复也必须带相同来源目录。不要在缺少检查点时手动删除账本或结果以重新调用。

离线回归：

```powershell
python -m unittest tests.test_deepseek_pilot -v
```

## 指标边界

原始攻击通过且新候选两次失败，按 `(parent_family_id, verified_option_match_v1, untrusted_note_v1)` 最多计一次新增可复现失败。另记录干净问题通过而良性对照失败的退化，以及要求两份良性问题都完成的发现口径。正式主指标仍为null。

这是对自编问题的规则失败观察，不自动断言是某种安全漏洞；应回到实际输出检查评分和原因。只在候选有效的家族里报告已观察到的配对数量。任何无效候选或中断存在时，全体净差指标留空；有效配对子集的差值单独命名。没有随机策略的等预算比较、独立来源资格或跨模型迁移，不据此主张回路A研究收益或模型总体安全水平。

所有结果位于Git忽略的 `runs/`，密钥不写入运行产物，不自动提交或推送。

## 2026-10-23实际结果与平台核对

本轮完成20个家族、117次实际模型请求（20次生成、97次目标回答），无重复付费调用。19个候选结构有效，1个因额外type字段隔离；19个有效候选各重放2次。干净基线20/20、固定注入20/20、生成注入重放38/38、良性对照19/19规则通过；未观察到新增可复现失败或良性退化。无效候选的未知配对仍保留，正式主指标为null，接纳数0。V/H共4个家族未调用。

本轮输入15119、输出1057 Token。首次三题另输入108、输出3，因此当天累计120次请求、输入15227、输出1060、总计16287 Token，缓存命中0。用户提供的平台截图逐项相符，费用截图显示当天累计0.01元；不能解读为每次请求收费0.01元。Token按高峰价估计0.038694元及内部预算占用2.34元分别是不同口径，不替代平台显示费用。

本地独立审计核对了117个不同响应ID、请求哈希、逐项费用结算、原生复评分、私有canary/字段、模型指纹、分区及准入，错误0。结果目录为 `runs/deepseek-pilot-20261023-v2/`，人工可读报告与截图核对为 `runs/deepseek-pilot-final-report-20261023/report.md`，均被Git忽略。
